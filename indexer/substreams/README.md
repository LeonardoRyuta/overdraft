# Overdraft — Aqua Substreams

The **Firehose-native twin** of [`indexer/subgraph`](../subgraph). Same data model
(`Maker` / `Token` / `Position` / `Commitment`), same four Aqua registry events,
same `committed = Σ Pushed − Σ Pulled` reconstruction — but emitted as **protobuf
via [Substreams](https://substreams.streamingfast.io/)** so it runs on chains The
Graph's hosted subgraphs can't reach.

This is the *"reach the chains subgraphs can't"* half of our The Graph
Composable-track story: Robinhood chain / Monad / HyperEVM are **Firehose-only**
(no subgraph support). **One module, re-pointed per chain** — change `network` +
`initialBlock` in `substreams.yaml` and the `AQUA_CONTRACT` const in `src/lib.rs`,
rebuild, run against that chain's Firehose. Same schema everywhere.

## What it indexes

Aqua registry `0x1111113ccf1426a8e30e2bff5e005d929bf6a90a`, four **non-indexed** events
(you must decode log *data* — you can't topic-filter; see `RECON-PROTOCOL.md` Q1/Q7):

| Event | Effect on state |
|---|---|
| `Shipped(maker, app, strategyHash, strategy)` | creates/re-activates a `Position` (id = `maker ++ app ++ strategyHash`) |
| `Pushed(maker, app, strategyHash, token, amount)` | `committed += amount` for that `(maker,strategyHash,token)`; adds token to the position |
| `Pulled(maker, app, strategyHash, token, amount)` | `committed -= amount` (clamped at 0) |
| `Docked(maker, app, strategyHash)` | marks the position + all its commitments inactive |

`committed` is the **QUOTED** (event-reconstructed virtual balance) side of Overdraft
coverage. The **BACKED** side (maker wallet balance ∩ ERC-20 allowance to Aqua) is
live state read at query time via `eth_call` and is intentionally *not* in this module
— mirrors the design note atop `../subgraph/schema.graphql`.

## Module graph

```
sf.ethereum.type.v2.Block
        │
        ▼
   map_events ──────────────► proto:overdraft.aqua.v1.Events   (decode 4 events, log order)
     │       │
     │       ├──► store_commitments  (updatePolicy: add, bigint)   Σ Pushed − Σ Pulled per commitment
     │       └──► store_positions    (updatePolicy: set,  proto)   lifecycle + token set
     ▼
   map_entity_changes ──────► proto:overdraft.aqua.v1.EntityChanges  (subgraph-shaped upserts)
     (inputs: map_events + both stores)
```

`map_entity_changes` emits the same `Maker/Token/Position/Commitment` shapes as the
subgraph so a downstream sink (the Substreams subgraph sink, SQL, or a custom
consumer) can upsert them. `Token.symbol/decimals` are left as `"?"`/`18` here (no
`eth_call` in a pure `map` module) and should be enriched by the sink; the address
`id` is always correct.

## Layout

```
substreams.yaml                 manifest — Aqua address, module wiring, network=mainnet, startBlock 25567141
proto/overdraft.proto           entity/output protobufs (source of truth)
abi/aqua.json                   the four Aqua events (non-indexed)
build.rs                        Abigen: abi/aqua.json → src/abi/aqua.rs at build time
Cargo.toml
src/lib.rs                      map + store modules (decode → fold → emit)
src/abi/{mod.rs,aqua.rs}        aqua.rs is @generated by build.rs (git-ignore it)
src/pb/{mod.rs, overdraft.aqua.v1.rs}   prost types matching proto/overdraft.proto
```

## Build

### Prerequisites
- **Rust** + the **`wasm32-unknown-unknown`** target.
- A working host linker (see the Windows note below).
- To produce a distributable **`.spkg`** you also need the **`substreams` CLI**
  (macOS/Linux only — see below). Building the raw `.wasm` does **not** require the CLI.

### Build the WASM module (no CLI needed)
```bash
cargo build --target wasm32-unknown-unknown --release
# → target/wasm32-unknown-unknown/release/overdraft_aqua_substreams.wasm
```

### Package into a .spkg (needs the substreams CLI)
```bash
substreams pack substreams.yaml       # → overdraft_aqua-v0.1.0.spkg
substreams info  substreams.yaml      # sanity-check module graph + proto
```

## Toolchain status (as built on this machine — native Windows 10, PowerShell)

| Component | Status on native Windows |
|---|---|
| `rustup` / `rustc` / `cargo` | ✅ installed (rustup via `winget`, rustc 1.98.1) |
| `wasm32-unknown-unknown` target | ✅ added |
| **MSVC toolchain** (`stable-x86_64-pc-windows-msvc`) | ❌ **build fails — `link.exe` not found.** The default host toolchain needs the MSVC linker (Visual Studio Build Tools, C++ workload) to compile the *host* proc-macros. Not installed on this machine. |
| **GNU toolchain** (`stable-x86_64-pc-windows-gnu`) | ✅ **this is the workaround.** `rustup toolchain install stable-x86_64-pc-windows-gnu` bundles its own mingw linker — no Visual Studio needed. Build with `cargo +stable-x86_64-pc-windows-gnu build --target wasm32-unknown-unknown --release`. **The `.wasm` builds clean this way (317 KB, valid WASM MVP module).** |
| `substreams` CLI | ⚠️ **no native Windows binary.** StreamingFast ships only `darwin`/`linux` release assets. `go install …@latest` is refused (the repo's `go.mod` has `replace` directives). It *can* be built from a `git clone` with `go build ./cmd/substreams` on Windows if you have Go, but the supported path is Linux/macOS/WSL. **Not required to build the `.wasm`; required only to `pack`/`run`.** |
| WSL2 | ❌ **hard-blocked on this machine** — `wsl` reports *"virtualisation is not enabled"* (BIOS/firmware; can't be fixed from software). So WSL was not an option here; the native GNU toolchain was used instead. |

**Bottom line on Windows:** the module **compiles to WASM natively** using the GNU
Rust toolchain (MSVC linker not required). Producing the `.spkg` and running against
data needs the `substreams` CLI, which is best run on Linux/macOS (or Windows-native
Go build of the CLI). If you have WSL2 available (virtualization enabled), the whole
flow — including the CLI — works out-of-the-box on Ubuntu.

### On another machine (Linux / macOS / WSL2 Ubuntu) — full flow
```bash
# Rust
curl https://sh.rustup.rs -sSf | sh
rustup target add wasm32-unknown-unknown
# substreams CLI (Linux example)
curl -L https://github.com/streamingfast/substreams/releases/latest/download/substreams_linux_x86_64.tar.gz | tar -xz
sudo mv substreams /usr/local/bin/
# build + pack
cargo build --target wasm32-unknown-unknown --release
substreams pack substreams.yaml
```

## Running against live data (to be added)

Substreams executes on a **Firehose** endpoint; it is not self-hosted like a subgraph.
To stream this module you need a provider endpoint + auth token:

- **The Graph Market** (Composable track): get a token, then
  ```bash
  export SUBSTREAMS_API_TOKEN=<token>
  substreams run -e mainnet.eth.streamingfast.io:443 \
    substreams.yaml map_entity_changes \
    --start-block 25567141 --stop-block +1000
  ```
- Or **StreamingFast** / any Firehose-enabled endpoint for the target chain.
- For the Firehose-only target chains (Robinhood / Monad / HyperEVM), point `-e` at
  **that chain's** Firehose endpoint and set `network` + the Aqua address accordingly.

The endpoint + token are deployment config, not code — wire them in when a Market
token is provisioned.

## Parity with the subgraph

The IDs are byte-identical to `../subgraph/src/aqua.ts`:
- `Position.id = maker ++ app ++ strategyHash` (raw-bytes concat)
- `Commitment.id = position.id ++ token` (raw-bytes concat)

and the fold logic mirrors the handlers exactly, including the defensive
`Pushed`-without-`Shipped` case and the `Pulled` clamp-at-zero. Same data, two
runtimes: subgraph where The Graph indexes it, Substreams where only Firehose reaches.
